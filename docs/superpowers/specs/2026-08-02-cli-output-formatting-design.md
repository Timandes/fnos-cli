# fnos-cli 终端输出格式化设计

日期：2026-08-02
状态：已批准

## 背景

`fnos-cli` 当前由 `src/utils/formatter.js` 负责普通输出，由 `--raw` 提供原始 JSON。现有普通输出存在两类主要问题：

- 对象数组虽然使用边框表格，但只读取第一行的字段，并按未格式化的字符串长度计算列宽；异构记录、中文、ANSI 色码和长值可能造成丢列或错位。
- 普通对象依赖 CPU、内存、磁盘和资源监控等字段的硬编码分支。嵌套数据经常被压成超长单行，不同命令的视觉层次和字段顺序也不一致。

本设计把人类可读输出统一为两种基础表现：二维表格和字段—值对象，并采用已确认的“现代分层”视觉方向。

## 目标

- 将对象数组稳定渲染为弱边框二维表格。
- 将普通及嵌套对象稳定渲染为字段—值分层布局。
- 统一标题、字段、值、状态和请求元数据的视觉层级。
- 正确处理异构记录、中文显示宽度、零值、布尔值、空值和长文本。
- 在交互终端中使用克制配色，在管道或重定向中输出无 ANSI 文本。
- 保持 `--raw` 的 JSON 内容与现有行为完全兼容。
- 用通用规则替代按命令持续增加的展示分支。

## 非目标

- 不改变 fnOS SDK 返回结构或请求行为。
- 不改变命令名称、参数、退出码以及 stdout/stderr 分工。
- 不新增主题、颜色或输出格式命令行选项。
- 不翻译 API 字段值，也不把普通输出承诺为稳定的机器解析格式。
- 不为每个命令建立独立的输出模板。
- 不改变 `--raw` 的缩进、字段顺序、数值精度或空值表达。

## 视觉方向

采用“现代分层”样式：

- 表格保留表头与水平分隔，不绘制完整外框和竖向网格。
- 标题与分组名使用强调色；普通字段名使用弱化色；值保持主要前景色。
- 文本左对齐，数字右对齐并使用等宽数字显示。
- 成功状态使用绿色符号，失败数据仍按原始值展示，不由格式化器改变命令退出行为。
- 请求元数据位于业务数据之后，以分隔线和弱化文本显示。
- 不依赖颜色表达唯一语义；去除颜色后仍能完整阅读。

## 数据分类与规范化

### 原始输出

`formatOutput(data, true, options)` 必须在任何规范化和着色之前直接执行：

```js
JSON.stringify(data, null, 2)
```

因此 `--raw` 不受终端类型、宽度、颜色环境变量或普通输出规则影响。

### 元数据

顶层或 SDK 的响应包裹层中，下列字段作为请求元数据处理：

```text
result, reqid, req, rev
```

如果响应包含非空对象或数组形式的 `data`，`data` 作为主要业务数据展开；其余非元数据字段仍作为业务字段保留。元数据只在主要业务数据之后显示一次，不在递归对象中重复。

元数据显示标签固定为：

```text
req    -> Request
reqid  -> ID
rev    -> Rev
```

字符串值 `succ` 单独渲染为带 `✓` 的 `Success`。其他 `result` 值使用标签 `Result` 并按原值显示，避免格式化器推断请求结果。

### 二维表格

满足以下条件的数组渲染为二维表格：

- 数组非空。
- 至少一项是普通对象。
- 每一项都是普通对象或 `null`。

列名按首次出现顺序汇总所有非空记录的自有可枚举字段，不只读取第一项。缺失字段显示为空占位符 `—`。嵌套对象和数组使用单行紧凑 JSON 表达；用户可通过 `--raw` 获取完整结构。

其他数组使用紧凑值表达。空数组显示 `[]`，不得被误报为“无响应”。

### 字段—值对象

普通对象使用两列字段—值布局：

- 标量字段直接显示为一行。
- 嵌套普通对象使用字段名作为分组标题，再递归显示其内容。
- 对象数组在所属字段标题下使用二维表格。
- 空对象显示 `{}`。
- 对象属性使用响应中的原始顺序；字段名只做可逆的视觉分词，例如 `maxFreq` 显示为 `Max freq`、`store_speed` 显示为 `Store speed`。

递归渲染必须携带缩进层级，不允许把多级结构压成一个无法阅读的长行。

## 标量显示规则

所有标量先保留其语义，再进行人类可读格式化：

- `null` 和 `undefined`：`—`。
- 空字符串：`""`。
- 布尔值：`true` 显示 `✓ Yes`，`false` 显示 `✗ No`；颜色不是唯一差异。
- 有限数字：右对齐，并使用英文千位分隔；不得改变小数精度。
- 非有限数字：使用 JavaScript 的字符串表达。
- 字符串：原样显示，不添加引号。
- 日期不做自动解析，避免误判普通字符串。

已知且语义明确的字段可以添加单位或现有展示转换：

- `temp`、`temperature`：`°C`。
- `busy`、`cpuBusy`、`memPercent` 及明确的百分比字段：`%`。
- `maxFreq`：`MHz`。
- `mem`、`swap` 分组中的 `total`、`used`、`free`、`available`、`cached` 和 `buffers` 继续按 1024 进制转换为 `GB`。
- `storeSpeed`、`netSpeed` 内的速率继续使用二进制 `MB/s`。

字段格式化规则集中维护，不得散落在具体命令分支中。无法确定单位的字段只显示原值。

## 终端宽度与颜色

### 宽度

交互终端通过 `process.stdout.columns` 获取可用宽度：

- 表格优先完整显示短字段。
- 超出宽度时，长文本单元格换行，不截断业务数据。
- 中文、全角字符和 ANSI 控制序列不得计入错误的单字节宽度。
- 未知终端宽度或非 TTY 输出不主动裁剪，以保留完整内容。

字段—值布局的字段列设置合理上限，过长字段名允许换行；值列获得剩余宽度。

### 颜色

仅同时满足以下条件时启用 ANSI 颜色：

- stdout 是 TTY。
- 未设置 `NO_COLOR`。
- `TERM` 不等于 `dumb`。
- 当前不是 `--raw` 输出。

管道、文件重定向和测试注入默认不含 ANSI 色码。颜色判断由命令执行层提供可注入的终端上下文，格式化器不直接修改全局输出流。

## 组件设计

### 命令执行层

`src/commands/runner.js` 继续负责调用 SDK 和写入 stdout，并把下列展示上下文传给格式化器：

```js
{
  color: boolean,
  columns: number | undefined
}
```

测试可以显式注入 TTY 状态和列宽，避免依赖执行测试时的真实终端。

### 响应格式化入口

`src/utils/formatter.js` 保持现有布尔参数兼容：

```js
formatOutput(data, raw = false, options = {}) -> string
```

入口只负责原始输出短路、空响应判断、响应规范化和渲染器分发。

### 表格渲染器

表格渲染器负责：

- 汇总列。
- 格式化单元格。
- 计算显示宽度。
- 分配终端列宽。
- 文本和数字对齐。
- 绘制弱边框布局。

使用成熟的终端表格库处理 Unicode 宽度、ANSI 字符和换行，避免在项目内重新实现终端排版算法。

### 对象渲染器

对象渲染器负责：

- 渲染字段—值行。
- 创建嵌套分组。
- 把对象数组交给表格渲染器。
- 渲染空对象、空数组和紧凑复杂值。

### 主题与值格式化

主题层集中定义标题、字段、弱化文本、成功状态和分隔线的样式。值格式化层集中定义字段分词、数字、布尔值及已知单位，不感知具体 CLI 命令。

实现使用三个专用运行时依赖：表格排版 `cli-table3`、轻量 ANSI 颜色 `picocolors`，以及 Unicode 显示宽度 `string-width`。最后一项作为直接依赖，使宽度分配和预换行与表格库使用相同的 Unicode 宽度规则。所有依赖必须支持 Node.js 18 和 CommonJS，不引入运行时网络访问。

## 数据流

```text
SDK response
  -> formatOutput
     -> --raw: JSON.stringify and return
     -> normalize response envelope
     -> separate business data and request metadata
     -> classify as table, object, array, scalar, or empty response
     -> render with terminal context
     -> append metadata footer
  -> stdout
```

`null` 或 `undefined` 的顶层响应继续显示明确的无数据提示。零、`false`、空字符串、空数组和空对象都是合法响应，不得与无响应混淆。

## 错误与降级

- 格式化器只接受 SDK 可序列化响应；遇到无法紧凑序列化的循环结构时，使用安全占位符，不让展示错误覆盖原命令结果。
- 未识别的对象形状走通用递归路径，不回退到命令专用逻辑。
- 终端宽度缺失或异常时使用无裁剪布局。
- 颜色不可用时只移除样式，不改变文字、符号、顺序或字段。
- 表格中的某行缺少字段时显示 `—`，不得抛出异常。

## 测试策略

新增独立格式化器单元测试，至少覆盖：

- `--raw` 输出与 `JSON.stringify(data, null, 2)` 完全相等。
- 异构对象数组汇总全部字段并保留零值。
- 表格数字右对齐、长值换行以及缺失字段占位。
- 中文字段和值的显示宽度不破坏列布局。
- 普通对象与多层嵌套对象形成字段—值分组。
- 对象中的数组自动进入表格渲染器。
- `null`、`undefined`、空字符串、空数组、空对象、`false` 和 `0` 的差异。
- 已知温度、百分比、频率、容量和速度单位。
- TTY 条件下存在预期 ANSI 样式，非 TTY、`NO_COLOR` 和 `TERM=dumb` 下无 ANSI。
- 元数据只显示一次并位于业务数据之后。

命令执行层测试覆盖终端上下文传递及 `--raw` 不着色。最后运行全部离线单元测试，并对表格和字段—值对象各进行一次固定响应的 CLI 级输出验证。

## 文档

README 的全局选项说明补充：

- 普通终端输出会根据 TTY 使用颜色和宽度。
- 管道与重定向自动关闭颜色。
- `NO_COLOR` 可以显式关闭颜色。
- `--raw` 适合脚本和机器解析。

- 截图所示磁盘响应使用弱边框二维表格，列对齐且无冗余完整外框。

- 全部离线单元测试通过。
