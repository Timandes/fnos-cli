# fnos-cli 0.3.0 Release Preparation Design

## Goal

Prepare `fnos-cli` 0.3.0 for a clean npm and GitHub release without changing CLI behavior. The release package must contain only runtime files and user-facing documentation, expose complete npm metadata, and remain covered by the existing unit and mock-server smoke tests.

## Scope

The release preparation will:

- define an explicit npm package file whitelist;
- add author, runtime compatibility, repository, issue tracker, homepage, and registry metadata;
- add automated assertions for the release metadata and file whitelist;
- verify the final npm tarball contents;
- rerun the complete unit and mock-server smoke test suites;
- prepare the v0.3.0 release notes and publication checklist.

It will not change commands, authentication, output formatting, SDK behavior, or any other runtime behavior. It will not create or push the v0.3.0 tag, create a GitHub Release, or run `npm publish` until those actions are explicitly requested.

## Package Contents

`package.json` will use a `files` whitelist containing:

- `bin/`
- `src/`
- `README.md`
- `CHANGELOG.md`
- `LICENSE`
- `docs/commands.md`

This keeps the executable, runtime source, license, changelog, and generated command reference while excluding development-only material such as `.github/`, `test/`, `scripts/`, `docs/superpowers/`, and `IFLOW.md`.

The existing `.npmignore` may remain as a secondary safeguard, but the `files` whitelist is the authoritative package boundary.

## Package Metadata

The following metadata will be added to `package.json`:

- `author`: `Timandes White`, matching `Timandes/fnos-ts-client`;
- `engines.node`: `>=16`, matching the documented minimum runtime;
- `repository`: `git+https://github.com/Timandes/fnos-cli.git`;
- `bugs.url`: `https://github.com/Timandes/fnos-cli/issues`;
- `homepage`: `https://github.com/Timandes/fnos-cli#readme`;
- `publishConfig.registry`: `https://registry.npmjs.org/`.

No npm credentials or tokens will be stored in the repository.

## Verification

The package metadata unit test will assert the exact whitelist and the release-critical metadata. This makes accidental additions to the npm package boundary visible in CI.

Release verification will then run:

1. `npm run test:all`, with `Timandes/fnos-mock-server` as the smoke-test backend;
2. `npm pack --dry-run --json` and an inspection of required and forbidden files;
3. `node bin/fnos --version`, which must print `0.3.0`;
4. `git diff --check` and a clean working-tree check.

Any failed test, missing required package file, unexpected internal file, version mismatch, or uncommitted change blocks release handoff.

## Release Handoff

The final handoff will include:

- the verified commit and branch state;
- the final tarball file list and size;
- a GitHub Release body derived from the existing `CHANGELOG.md` 0.3.0 section;
- the exact tag, npm publication, and GitHub Release steps still requiring explicit approval and authenticated tooling.
