# fnos-cli 简体中文与英文设计

日期：2026-10-30
状态：待用户确认

## 意图与目标

CLI 提供简体中文（`zh-CN`）和英文（`en`），默认简体中文。用户已选择持久保存语言偏好，并允许命令行参数和环境变量临时覆盖。

覆盖 CLI 自身生成的帮助、参数说明、参数错误、认证与 OAuth 提示、server 选择、运行结果标签及补全说明。语言选择对所有命令层级、隐藏点号兼容命令、无参数帮助和错误路径一致生效。

保持命令名、参数名、SDK 方法及参数、退出码和 stdout/stderr 分工。`--raw` 返回的 JSON（包括 CLI 生成的登录摘要）保持原键、原值和格式。服务端消息、SDK 原始诊断、用户数据与技术标识按原文显示；CLI 自身提供的解释和建议使用所选语言。

## 方案比较

1. 仅 `--lang` 和 `FNOS_LANG`：实现较小、没有配置写入，但需每次指定或配置 shell。
2. 持久偏好加临时覆盖：增加配置命令和偏好读写；无需配置 shell，适用于同机日常使用。**用户已选择此方案。**

实现建议使用项目内的轻量字典和插值函数，不新增国际化依赖。当前只有两种语言，文本以 CLI 提示为主，不需要复数、日期或货币规则；以后可在同一入口扩展。

## 语言选择

优先级从高到低：

1. 全局选项 `--lang <locale>`，同时支持 `--lang=en`。
2. 环境变量 `FNOS_LANG`；空字符串视为未设置。
3. `~/.fnos/settings.json` 顶层的 `language` 字段。
4. 默认 `zh-CN`。

只接受 `zh-CN` 和 `en`，不从 `LANG`、`LC_ALL` 或操作系统语言推断。命令名与其他参数值中出现 `--lang` 不得被误读；`--` 后的内容不作为全局选项。参数可出现在命令之前、之后或子命令之间；重复指定时以最后一个为准，沿用 Commander 的选项行为。

必须在生成帮助及处理 Commander 参数错误之前确定语言，不能只依赖 `preAction`。语言上下文属于本次程序调用，不通过修改 `process.env` 或可变的全局默认值传播，避免多次调用或测试相互污染。

显式参数或环境变量的值无效时，输出支持值提示并返回参数错误码 `4`；显式有效参数覆盖无效环境变量。无法由更高优先级确定语言时，错误提示使用简体中文。缺少 `--lang` 的值同样返回 `4`。

缺失、无法读取、损坏或包含不支持语言值的设置文件，不影响帮助、版本号、补全脚本等无需凭据的命令：语言读取回退到默认中文。该只读回退不创建、不迁移、不改写文件。真正需要读取或写入配置/凭据的命令仍沿用原有配置错误处理，不把损坏文件当作空配置覆盖。

## 持久偏好的交互

新增公共命令组 `config`，只开放 `language` 这个键，不提供读取整个设置文件的入口：

```sh
fnos config set language en
fnos config get language
fnos config unset language
fnos --lang en user --help
FNOS_LANG=en fnos user info
```

- `set language <locale>`：校验并保存偏好。只修改顶层 `language`，不自动登录或访问 NAS。
- `get language`：展示已保存偏好（未设置时为 `null`）、本次生效语言及来源。来源使用稳定标识 `argument`、`environment`、`settings`、`default`。
- `unset language`：删除顶层偏好；未设置时成功且不创建文件。本次覆盖仍按优先级生效。
- 其他键或错误值返回 `4`，不修改配置，也不打印凭据。

设置和清除的成功消息使用本次调用启动时选定的语言，新偏好从下次调用生效。建议成功摘要包含 `language`（保存后的值，清除后为 `null`）；`get` 摘要固定为 `{ language, effectiveLanguage, source }`。`--raw` 仅输出这些稳定 JSON 字段；普通输出翻译标签和值的说明。

设置更新复用现有 settings 锁和原子保存，保留 server 记录、旧版顶层凭据和其他未知设置；仅修改偏好不触发凭据迁移。配置目录保持 `0700`、文件保持 `0600`。与登录、退出和 OAuth 刷新并发时，均在同一 settings 锁内重新读取并合并，避免丢失另一方修改。

## 翻译结构与边界

- 两种语言维护相同的一组消息键，插值变量按名称传入；测试检查键集合和插值占位符一致。
- 命令目录集中提供领域、111 条业务命令及业务选项的翻译。公开帮助、补全和文档生成复用这些元数据，不复制命令结构。
- Commander 的帮助标题、帮助命令描述、默认值说明、未知命令/选项、缺少参数、无效参数及常见建议一并覆盖。保留动态命令名、参数值和技术标识。
- 认证、OAuth、网络诊断、配置和锁相关的 CLI 自有文案使用统一入口。服务端原文及 `errno` 保留，不根据自然语言字符串猜测错误类型或错误码含义。
- 输出中的成功/无数据、布尔值、请求元数据、认证摘要和配置摘要标签使用所选语言。常见且含义明确的 API 字段标签可用集中映射翻译；无法识别的字段继续使用现有分词规则，不猜测业务含义。响应字符串值不自动翻译。
- 数字格式、单位、颜色规则、Unicode 换行和脱敏规则沿用现有行为。CLI 自有日志文案使用所选语言，SDK 内部日志保留原文。
- 补全选项包含 `--lang` 的两个候选，配置键和值也提供静态候选。生成脚本中的说明使用生成时语言，之后改变偏好需重新执行 `fnos completion install zsh`；不为静态说明增加运行时 Node 查询。
- 内部 `__complete server` 继续只输出 server 名称，不加载完整国际化、Commander、SDK 或日志模块。

## 文档与非目标

README 继续以中文为主，补充语言优先级、三个配置命令、临时覆盖和重新安装补全的示例。现有英文 `docs/commands.md` 保留为英文参考，生成器显式选择英文，保证与终端默认语言独立且生成结果稳定。

本次不创建整套英文 README 或中文命令参考，不翻译任意 API 响应内容，不改 SDK、不做 NAS 真机操作、不引入系统语言自动检测或在线翻译。

## 验证与验收

- 默认中文、两种显式语言、四级优先级、无效值、缺值、等号语法、选项位置、重复选项、`--` 边界及类似选项值的输入。
- 语言偏好跨进程保存，设置/清除不破坏旧配置和并发写入；配置损坏时查询与写入安全失败，帮助和版本仍可使用。
- 两种语言分别验证顶层/分组/叶子/点号帮助、Commander 错误、参数校验、密码和 OAuth 提示、server 选择以及普通结果输出。
- 相同响应在两种语言中的 `--raw` 输出逐字相同；错误退出码、秘密脱敏和不访问网络的路径保持现有约定。
- 翻译键及插值一致，全部命令与选项具备两种说明；生成的 zsh 脚本通过语法和候选检查，动态补全仍走轻量路径。
- 更新旧测试，使验证英文文案的用例显式选择英文，并新增默认中文与优先级测试；不通过强制全局英文掩盖默认语言行为。
- 运行适用的离线测试和文档生成校验。已知原始基线：271 通过、2 失败（LOGO 登录测试、受沙箱本地监听限制的 OAuth TLS 测试）；实现验收时单独核实，不将其隐藏为新增测试通过。
