# fnos-cli 人类与大模型友好的命令行文案设计

日期：2026-11-01
状态：设计草案，待用户审阅；不包含产品实现授权

## 意图与决策依据

用户希望命令行文案同时适合人类和大模型阅读，让模型从帮助中理解用途、实体关系（ER）、场景与限制，并可将其作为操作说明。最初要求每条 usage 单行、首句总结；随后明确允许放宽单行约束，由设计者判断最合适的呈现。

用户进一步指出，逐层递进会增加模型调用 `--help` 的次数，希望同一命令在不同场合使用相同的 usage。因此本设计修订为“一份完整说明，多入口原样复用”：帮助入口仅决定展示哪些命令，不决定某条命令展示多少信息。首句总结保留为所有命令描述的硬性要求。下文 usage 指命令的完整说明块，包含调用语法和操作契约，不仅指 Commander 的 usage 语法字符串。

当前代码基线为 567803d：21 个业务领域、111 条业务命令，另有 login、logout、auth.status、config、completion。已有 catalog 的 required、type、defaultValue、allowedValues、min/max 等元数据；运行时校验由 options.js 等执行，Commander 注册并未完整体现这些语义。现有帮助、补全、英文参考复用了命令树和 catalog，适合渐进扩展。

## 方案比较

| 方案 | 优点 | 代价与结论 |
|---|---|---|
| 完整语义压在单行描述 | 单条文本包含大量信息 | 宽度失控，命令列表难扫读；不采用 |
| 单行摘要＋普通帮助分层详述 | 列表短、便于导航 | 需继续查询才能获得完整信息，用户已指出调用成本；不采用 |
| 一份完整说明、多入口原样复用 | 一次根帮助获得完整上下文，命令说明始终一致 | 顶层输出更长，用首句和排版支持扫读；本次推荐 |
| 普通帮助＋独立 Agent 文档或模式 | 可单独提供大规模上下文 | 多一个发现入口，容易内容漂移；本期不新增 |

## 目标、范围与边界

- 覆盖全部公开命令组、业务命令、辅助命令、参数说明、CLI 自有成功/失败提示和帮助导航；隐藏点号命令复用对应语义。
- 普通帮助足以回答：做什么、操作谁、标识哪里来、何时使用、怎样调用、会产生什么影响、结果意味着什么、下一步是什么。
- 中文和英文表达等价，命令名、参数名、JSON 键和技术标识保持稳定。
- 不新增业务能力、自动确认、重试、预查询、网络验证或权限检查；文案不得声称新增了这些行为。
- 不改变参数解析、默认值、SDK 调用、认证、退出码、stdout/stderr、原始 JSON 或服务端消息；发现运行时缺陷另行处理。
- 根帮助一次展示全部公开命令的完整契约，组帮助展示该组及全部公开后代，叶子帮助展示该命令；不要求逐层查询来补足同一命令的信息。不保证调用工具或模型上下文能容纳任意长度的输出，输出被外部截断时需按组取子集。
- 不构建完整数据库 ER 图，不猜测不可见的服务端数据结构、权限、枚举含义、单位或版本要求。

## 帮助的信息架构与一致性

同一语言下，同一命令的规范调用语法、首句、用途、关系、参数、限制、影响、结果、示例和相关命令在所有帮助入口保持相同内容、相同顺序。只允许因终端宽度发生排版换行，不允许按入口删减段落或改写成短摘要。使用完整命令路径作为标题和语法，避免离开父级上下文后产生歧义。

每次输出分为入口介绍、公共规则、命令说明块。公共规则包含全局选项及适用的通用认证规则（含通用互斥条件、默认行为），每种规则每份输出只打印一次；每个命令块标明适用规则类别，仅展开本命令特有的条件与影响，不重复通用规则。业务专属选项始终在命令块内。命令块之外的公共规则随入口包含的命令范围选择，命令块本身保持不变。叶子帮助也输出其所需的公共规则，因此阅读本次帮助即可获得全部适用条件，不依赖另一条 `--help`。

### 顶层 `fnos --help`

首句概括产品用途和目标系统；随后放公共规则、最短上手路径，以及完整公开命令树：各组的完整说明与其全部后代命令块，包括辅助命令。以稳定的领域顺序、标题及缩进组织，全部内容直接写入原有输出流，不新增分页确认、交互或默认截断。上手路径展示命名 server、一个只读查询、`--raw` 的用途，不放真实凭据。

用短段说明：server 是本地连接名称，绑定目标 endpoint 与认证记录；业务命令作用于所选目标；模型或脚本应显式指定 `--server`，避免依赖交互选择。这里是使用建议，不新增参数强制要求。

### 命令组 `fnos <domain> --help`

展示该组完整说明（首句说明领域职责，后续说明核心实体、常见查询链路和相邻领域的区别），以及全部公开后代命令的完整说明块。组说明和每个后代块与根帮助中的对应内容相同。认证和全局选项继续可见。此入口用于选取较小范围，不用于解锁根帮助缺失的详情。

### 叶子 `fnos <domain> <command> --help`

展示该命令的完整说明块，内容与根/组帮助相同。命令块固定顺序：

1. 用法：一条规范调用语法。
2. 摘要：一句完整的“动词＋业务对象＋关键结果”。
3. 用途：一到两句适用场景，必要时指出容易混淆的相邻能力。
4. 对象与关系：目标作用域、实体/标识类型、标识来源、关联与前置查询。
5. 选项：业务选项及其完整契约；通用认证/全局选项在本次输出的公共规则中列出一次。
6. 条件与影响：跨参数约束、交互/权限/硬件/版本条件、操作影响和重要能力边界。
7. 结果：返回对象的业务含义、已验证的关键字段/单位/空结果语义、成功判定和 `--raw` 用途。
8. 示例：通常一到三个，包含最短调用、必要的前置发现或容易误用的情况。
9. 相关命令：下一步及其目的；命令引用必须真实存在。

无内容的可选小节省略，不能输出空标题或“无特殊说明”。摘要、作用域、影响、参数契约和至少一个有效示例是每个公开叶子的最低要求；无业务参数也应明确作用于当前用户、所选服务器或本机配置中的哪一种。

普通叶子帮助包含其关键共享约束，不要求读者回到根帮助才能理解互斥条件和执行影响。共享段落以模板生成，避免人工复制。

## 排版与长度

- 各入口用完整命令块组成列表，不另造摘要版列表。每块首句尽量简短，正常宽度目标为 80 列、兼顾 100/120 列，以标题和留白帮助人类快速跳读。
- 不为“视觉单行”截断语义或强行横向溢出。窄终端允许按显示宽度自然换行；调用语法源文本保持一行，过长时终端可自然折行。
- 每个命令块的总结句独立成段，后面的说明可换行和分节。参数摘要简短，复杂输入结构或跨参数条件放到对应说明段并明确参数名。同一块在根/组/叶子入口使用相同结构，不因位置不同切换详细程度。
- 中英文按显示宽度处理，不用字符串字符数计算中文列宽。颜色仅辅助辨识，不承载必需语义；沿用 NO_COLOR、管道与 TERM=dumb 规则。
- 不设僵硬的整页行数上限。优先删重复话语，不隐藏影响或限制；既有无参数调用、错误及显式帮助路径的输出流和触发方式保持，帮助一旦展示便遵循相同完整性规则，不因来自错误路径而降级成另一份说明。根帮助较长是减少查询轮次的明确取舍，排版不能消除总阅读量与上下文占用。

## 文案规范与 ER 契约

摘要禁止“获取相关信息”“管理对象”等缺少范围的说法。当前用户、指定用户、全部可见用户、管理员视图要明确区分。查询配置、检查运行状态、触发检测、修改远端、本地配置修改是不同操作，不从 get/list 名称自动推断副作用。

实体关系围绕可执行任务描述，至少处理：

- 作用域：标识是服务器内、用户内、本地配置内，还是其他范围。
- 标识：设备名、路径、名称、整数 ID、UUID、WWN 等准确类型。
- 来源：前置命令及已验证响应字段；只知道前置命令时不虚构字段。
- 衔接：哪些返回值可以传给哪个选项，是否需要转换。
- 关系：拥有、成员、关联、挂载、引用等；仅在证据支持时写基数和关联键。

首批关系覆盖 server/endpoint/认证、磁盘与 SMART、存储阵列与标识、文件与路径/ACL/回收站、用户与用户组/2FA、接口与网络设置、共享服务与目录/链接、iSCSI target/LUN/initiator、Docker 项目/容器/镜像/网络、任务与状态/分页。列表表示审计范围，不预先保证服务端返回了可连接所有实体的外键。

不同命令对同类实体可能使用不同路径格式，尤其 `file getAcl` 的 vol 前缀路径，必须按实现与证据逐一说明，不能统一改写成宿主机绝对路径。未知关系允许明确标注未确认，并提供已核实的下一步，不能用不确定数据生成可复制调用。

## 参数契约

每个参数的帮助说明包含已存在的：必填/可选、类型、默认行为、合法值或范围。这里要区分“参数是否必须提供”和“提供参数后是否必须带值”，避免把 Commander 的 requiredValue 当作业务必填。

- 布尔值：例如 `--all <boolean>` 必须传 true/false；无值开关与之区分。
- 默认值：从 catalog 读取，区分默认 null/空数组和用户显式传空串；不声称 SDK 默认值等同于 CLI 默认值。
- CSV：分隔、空白处理、空项处理、最少元素数以及逗号本身能否出现在值中，严格匹配 parseValue 的行为。
- JSON：区分对象与非空对象数组；仅给已验证的字段结构和 POSIX shell 引用示例，不把示例描述成已执行结果。
- 枚举：同时提供值与已确认业务含义。`backup --direction 0/1`、`network --type 0/1` 等未确认含义应显式标注，不猜测。
- 分页/筛选：说明默认页码和条数、过滤对象、是否自动遍历，按实际实现说明单页行为。
- 共享认证：说明 `--server` 与临时 endpoint/username/password 输入互斥、临时凭据完整性、非交互密码输入及 OAuth 的真实交互边界。
- 权限/版本：CLI 本地校验、SDK 校验、服务器要求分开表述；没有已核实依据不写“管理员必需”或最低固件版本。

## 结果、限制与反馈

结果说明不承诺未验证的响应 schema，不因 raw JSON 里出现数字就猜测单位。说明 `--raw` 保留响应结构、正常格式便于阅读；不能宣称 raw 自动脱敏所有服务端业务字段。CPU 范围、资源采样窗口等只有查实后才解释。

对可能多响应的方法按 runner 的实际聚合/失败判定描述，不把 HTTP 成功等同于全部业务成功。参数类错误、认证类错误、请求/业务失败的退出码沿用现有行为；Commander 解析错误单独核对，不能统一重写为参数错误码 4。

CLI 自有失败文案按“发生了什么；涉及哪个对象或参数；怎样修正”组织。只在确定错误类型时给具体建议，不从服务端自然语言猜测是否需要重新登录。缺 scope、权限不足、DNS、证书、超时不能一律导向重新授权。不扩展运行时错误分类，不改变错误协议；无类型依据时保留原始诊断并添加通用排查入口即可。

成功消息说明已完成的动作和作用域；`auth.status` 必须突出“读取本地认证元数据，不验证服务器访问”，`logout` 只承诺清除本地记录，不声称撤销服务端 token。`completion install` 说明写入位置和后续 shell 配置步骤，`config` 区分保存值与本次有效值。服务端正文、SDK 原始诊断、用户数据继续保留原文，现有脱敏行为保持。

## 示例草图

以下是拟议命令块的排版和语义，不是新增命令或执行结果；此块在根/组/单命令帮助中内容相同。认证/全局选项在每次实际帮助输出的公共规则中展示。

```text
用法：fnos store diskSmart [options]

读取指定磁盘的 SMART 信息。

用途：检查磁盘健康指标；此命令读取信息，不启动 SMART 自检。

对象与关系：
  --disk 是所选服务器返回的磁盘设备名。
  先运行 store listDisk，从 disk[].name 取得值，再传给 --disk。

选项：
  --disk <disk>  磁盘设备名。必填；字符串。

条件与影响：
  适用本页公共规则中的“业务命令认证”。
  使用所选服务器的认证和访问权限；不保证所有设备返回相同 SMART 字段。

结果：
  返回该磁盘的 SMART 信息；--raw 保留原始 JSON 响应结构。

示例：
  fnos store listDisk --server office --raw
  fnos store diskSmart --server office --disk '<上一步返回的设备名>' --raw

相关命令：
  fnos store listDisk --help  查看磁盘发现方式及热备盘筛选参数。
```

设备名来源已由已安装 SDK 的 Store 方法及 tools/list_disk_temperatures 核对。占位符必须替换，不使用可能被模型误认成真实设备的写死示例值。写操作示例显著说明影响，不捏造确认或 dry-run 开关。

## 数据与实现方向

复用现有 catalog、命令树及国际化入口，建立单一文案契约。建议每个命令维护 summary、purpose、entityRefs、relations、constraints、effects、resultNotes、examples、relatedCommands；参数的 required/type/default/枚举/范围继续引用现有执行元数据，不在说明数据中手写第二份值。具体字段和模块拆分留给实施者。

业务命令由现有注册逻辑接入契约，辅助命令通过相同适配层提供契约，不为了统一文案而改写业务执行器。统一 renderer 根据语言和命令身份生成唯一的完整命令块；根/组/叶子入口只选择块集合，不将所在层级作为块内容生成条件。不使用 Commander 默认的摘要子命令列表来替代这些块。内部 description 可保留首句以供补全消费，但不能用它生成另一种精简帮助。

隐藏点号入口的说明块使用规范空格命令路径，保留相同语义；入口外可标注本次调用的是兼容拼写。隐藏别名仍不加入根帮助或补全，不重复输出同一命令。自动生成的 help 导航指令也应有统一说明，但不是业务命令目录中的独立实体。

三处输出消费同一来源：所有终端帮助用相同完整契约，英文 docs/commands.md 生成同样的完整契约，zsh 候选标签使用契约首句（补全标签不是另一份 usage）。保留 README 中文导航及已有英文参考的语言策略；本期不另建 Agent 模式、全量 help 导出命令或独立中文参考，普通根帮助本身已经完整。

ER、结果字段、版本/权限等非执行元数据需有内部证据记录，注明实现/SDK 文件、文档或测试样例和核验范围。该记录属于项目设计/验证资料，保存在仓库，不写入个人知识库；不将内部路径塞入面向用户的帮助。第三方 CLI 的能力与本项目分开核验。

## 覆盖与交付策略

先完成全部公开入口的文案清单：按命令标记摘要、作用域、参数、关系、影响、结果、示例、中英文、证据状态。111 条业务命令从 catalog 枚举，辅助命令从公开命令树枚举；隐藏别名复用而非另写。

先以 store diskSmart、file rm、user getUserTwofaConfig、network getInfo、docker listContainers、auth.status、login、config get 和 completion install 试写并检查版式，再覆盖其余命令。以上是文案样本，不执行远端操作。完整交付前不得把样本覆盖宣称为全量覆盖。

对信息缺口使用三类状态：已核实、明确不适用、尚未确认。完成要求是所有入口都完成审计，已知约束均被呈现，未知信息被如实标出；不以补齐未经证实的业务含义为前提，也不把“尚未确认”当作免除代码可证实事项核查的理由。

## 验收

- 结构：每个命令块有总结性首句并覆盖最低契约；无空节；相关命令和选项引用可解析。根帮助完整列出全部公开组/命令；组帮助完整列出组及其全部公开后代，无隐藏别名重复。
- 入口一致性：相同语言和宽度下，从根帮助、组帮助及叶子帮助提取的同一命令块逐字相同；跨宽度仅允许换行变化。普通 help 导航和隐藏兼容入口也复用同一块，公共规则按本次输出只出现一次。
- 一致性：默认值、必填、类型、枚举与运行时元数据一致；共享认证条件和隐藏别名复用一致；中英消息和占位符齐全。
- 呈现：代表性顶层、组、叶子、写操作和辅助命令在两种语言、80/100/120 列及窄终端下检查，允许合理换行、不丢信息；管道输出无 ANSI。
- 自足性：只提供一次完整根帮助时，能完成跨命令的选型、输入发现与约束理解，不再依赖后续帮助调用；只提供叶子帮助时，也能识别目标/作用域、必要输入、标识来源、前置步骤、影响和关键限制。实际查询实体数据仍是正常业务调用，不计作缺失帮助。
- 场景：磁盘发现到 SMART、文件删除默认回收站行为、用户 ID 到 2FA 查询、接口名到详情、容器包含停止项、单页共享链接、离线认证状态与实际访问的区别。
- 评估方式：用固定问题和答案要点进行人工/代理阅读审查，不引入付费模型服务或“任何模型均可”的保证。未知事项的正确答案是明确未知，不允许编造。
- 回归：现有解析、调用参数、raw 输出、退出码、日志脱敏、语言选择、补全和离线帮助保持；帮助不访问 NAS、不修改本地凭据。示例用解析/注入方式验证，写操作不对真实 NAS 执行。
- 文档生成确定性及与命令契约的一致性纳入检查；避免为每一行文案写脆弱的全文快照。

当前隔离工作区基线：npm test 在允许本地监听后 350 passing、1 pending。受沙箱监听限制的首次失败不视为产品失败，也不隐藏待执行项。
