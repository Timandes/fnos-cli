# fnos-cli 人类与大模型友好的命令行文案设计

日期：2026-11-01
状态：分层方案已确认；用途扩写与叶子详细帮助已实施并验证

## 决策与范围

用户在比较完整说明复用与分层帮助后，确认采用分层方案，并要求顶层命令和组内子命令的一句话用途说明扩写到原来的约两倍，先中文后英文。此决定取代此前“根帮助展开全部完整命令块”的草案。

采用既有三级结构：根帮助选择领域，组帮助选择命令，叶子帮助解释执行。首句或开头分句概括用途，随后补充对象范围、适用场景、关键默认行为或能力边界；不为凑字数加入未知能力。

本轮覆盖 21 个领域、111 条业务命令及公开辅助命令的用途描述。修改中英字典并重新生成英文命令参考；沿用现有命令树、国际化和帮助渲染，不新增分节 renderer、参数、依赖或业务功能。此前叶子详细说明样稿保留为后续设计方向，不在本轮声称已实现。

## 文案要求

- 中文先定稿，再逐条翻译英文；技术标识不翻译。
- 各命令描述保留概括用途的开头，增加有价值的范围/场景，不堆叠空话。
- 扩写长度约为原来两倍，以信息准确和自然表达优先，不设置机械字符数门槛；特别短的领域标签可以更充分展开。
- 说明必须区分当前用户与指定用户、本地记录与远端状态、读取与写入、配置与运行状态。
- 优先说明已有默认值（如排除热备盘、包含停止容器、默认请求移入回收站）或标识用途（如设备名用于 SMART 查询）。
- 不猜测未核实的返回字段、单位、版本、权限、枚举含义、任务状态或实体关联。
- 描述源文本不插入换行。保留终端按宽度自然换行的行为，不以不换行为由截断内容。

## 实现与兼容性

保留现有英文消息键，在 zh-CN 和 en 字典中分别维护对应扩写后的文案。无需修改 catalog 的方法、选项和执行元数据。原有帮助、补全和英文参考通过相同 t() 入口消费这些描述，避免另建文案系统。

命令名、参数、解析、默认值、SDK 调用、认证行为、退出码、输出流、原始 JSON 和服务端消息不变。隐藏点号形式复用相同描述。英文参考通过原生成器更新，不能手工维护另一份。

## 验收

- 逐项确认所有领域/业务命令/公开辅助命令的中英用途说明均已扩写且含义一致。
- 实际检查根、store 组、store.listDisk 叶子帮助在两种语言下的输出，以及所有业务组的帮助。
- 检查描述无源文本换行、标识准确、无臆造能力，重点核对默认值和本地/远端边界。
- 英文命令参考生成确定，补全继续通过已有校验，全部既有离线测试保持通过。
- 这是可逆的文案修改，不新增只镜像文案字符串的测试；运行现有行为测试并人工审阅文案。

## 已知基线

567803d 上的隔离工作区测试：允许本地回环监听后 350 passing、1 pending。本轮在 feature/cli-copy-design 内完成，不操作真实 NAS。

## 第二阶段：叶子帮助（用户于摘要完成后要求继续）

在现有摘要和选项之后追加用途、对象与关系、参数契约、条件与影响、结果、示例、相关命令。根与业务组保持分层摘要，补全仍只读 description。覆盖111条业务命令、点号兼容形式以及登录/退出/认证状态、配置叶子和补全操作；completion 本身既能执行又有子命令，也应有操作说明。

详细数据使用独立模块，按领域提供场景和对象上下文，命令特有的关系、影响和限制显式覆盖；不从方法名称自动推断副作用。对象与关系明确所选服务器/当前账户/本机配置的范围，以及已知标识来源。未确认的关联字段、枚举含义和JSON内部结构如实标注。

参数契约直接读取catalog，展示必填性、类型、默认值、枚举和范围；布尔值显式带值，CSV按实际拆分规则说明，JSON区分对象与非空对象数组。缺省null/空数组不等同于显式传空串。现有解析与校验逻辑不变。

每个操作有影响说明和可替换占位符的示例；业务命令选用显式server，不执行示例或访问真实NAS。静态示例使用结构化token数组渲染，保持命令单行便于复制。关系引用使用真实规范命令路径，点号入口内容相同、仅调用语法随入口变化。

辅助命令明确本地配置变化、远端登录、OAuth交互边界、stdout脚本输出、配置语言优先级以及认证状态不能证明在线授权。通用认证约束按实际业务/登录/本地操作分别适用，不能把业务server互斥规则错误套用于login。

通过纯函数生成本地化章节，由现有帮助渲染追加；原有帮助/错误输出流与语言上下文保持。普通文本按显示宽度换行，示例token不被程序拆断。英文命令参考消费同一章节数据，中文优先再译英文。

验收：TDD覆盖双语完整章节、按入口一致、全目录覆盖、真实参数约束、写操作影响、辅助命令边界、无凭据/网络副作用、静态示例经替换占位符后通过既有参数解析、文档一致性和窄终端。已有全量测试必须通过；涉及本地TLS服务的测试需要回环监听权限。

第二阶段验收：最终 npm test 为 359 passing、1 pending；分组/点号业务入口双语共444条渲染检查通过。独立审阅发现的 Markdown 参数占位符问题经失败测试确认后已修复。未执行真实 NAS 操作；未验证的字段/枚举含义在帮助中明确标注。
