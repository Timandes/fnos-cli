# fnos-cli 0.4.0 Release Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the repository metadata, release notes, and npm package contents for the `fnos-cli` 0.4.0 release without committing, tagging, pushing, or publishing.

**Architecture:** Treat the release as a metadata-only change on `release/0.4.0`: first make release-documentation tests describe the intended version and changelog, then synchronize npm metadata, finalize the Keep a Changelog entry, and run the complete offline and packaging verification gates. Existing runtime code and generated command documentation remain unchanged.

**Tech Stack:** Node.js 18+, npm, CommonJS, Mocha 10, Keep a Changelog, Semantic Versioning.

## Global Constraints

- Work only on branch `release/0.4.0` in the isolated release worktree.
- Set the package version to exactly `0.4.0` in `package.json`, `package-lock.json`, and `package-lock.json`'s root package record.
- Date the 0.4.0 changelog entry `2026-08-04` and retain an empty `Unreleased` section for future changes.
- Release notes must cover named multi-server authentication, responsive structured output, zsh completion, migration/non-interactive behavior changes, and hardening fixes implemented since `v0.3.0`.
- Do not modify runtime behavior or dependency versions.
- Do not commit, tag, push, or publish.
- Any later commit message must use English Conventional Commits and must not contain `Co-Authored-By`.

### Task 3: Finalize the 0.4.0 changelog

**Files:**
- Modify: `CHANGELOG.md`

**Interfaces:**
- Consumes: user-facing changes represented by commits after `v0.3.0`.
- Produces: an empty `Unreleased` heading followed by a dated 0.4.0 entry with Added, Changed, and Fixed sections.

- [ ] **Step 1: Release the current Unreleased notes and add missing user-visible changes**

Make the top of the changelog contain these headings and facts:

```markdown
## [Unreleased]

## [0.4.0] - 2026-08-04

### 新增

- login、logout 和全部业务命令支持使用 `--server` 管理和选择多 server 凭证
- 多个已保存 server 可在交互终端中通过编号列表选择
- 新增响应式结构化输出，支持分层字段—值布局、对象数组表格、终端宽度换行和克制配色
- 新增 zsh Tab 补全，覆盖命令、选项、有限值和已保存 server 名称，并提供显式安装命令

### 变更

- 旧版顶层单 server 凭证会一次性升级为 `servers.default`
- 非交互环境存在多个 server 时必须显式提供 `--server`
- 管道、文件重定向、`TERM=dumb` 和 `NO_COLOR` 环境保持无 ANSI 色码输出

### 修复

- 更新认证信息时始终写回当前选中的 server
- 强化窄终端下 Unicode、CJK、emoji 和深层嵌套值的无损换行
- 清理输出中的终端控制序列，避免其影响布局或泄漏到人类可读输出
- 强化 zsh 补全脚本安装时的符号链接、临时文件和失败恢复处理
```
